# Security policy

Experimental community plugin.

## Reporting issues

Use GitHub Issues for non-sensitive bugs. Keep credentials, personal data and unredacted session logs out of public issues. For vulnerabilities, contact the repository owner through GitHub to arrange a private reporting channel. [Issues](https://github.com/abinadwan/DSH-ABINADWAN-Plugins-Suite/issues)

## Current data handling

**Environment & Context** reads UI-facing session/workspace summaries and projected token usage. It registers zero shell, filesystem or credential tools. The suite browser carrier reads the access-checked Host plugin inventory to follow Component enablement and subscribes to lifecycle events. When inventory is unavailable, Component UI pauses until a successful refresh.

**Humanizer** registers a local, original instruction body in DSH's runtime Skill registry. Its instructions operate on authorized text within the agent's existing context. Text sent to the agent follows the configured model/provider's normal handling. The plugin adds zero dedicated rewriting endpoints or background rewriting requests. Disabling withdraws future Skill discovery and loading. Already loaded instructions remain in the conversation's model context.

**My Profile (internal Personal Profile module)** is disabled by default. When enabled, it stores one unified profile (optional preferred name, nationality, gender, response preferences, custom instructions and one saved access policy per field) through the native Harness Settings service (`settings.describe`/`settings.replace` with an expected revision), in the active Harness Profile's configuration. **This plugin does not encrypt these settings or JSON backups**; anyone with access to the Profile configuration files, or to a copied backup, can read them. The storage boundary is the OS account, file permissions and any disk encryption already in place. Do not enter passwords, keys, health, financial or other sensitive information.

Personal Profile registers a native system-prompt section for supported top-level native agent steps. Saved style, language, traits and presets follow the configured model, including cloud providers. Free-form custom instructions require explicit saved consent; editing, restoring or resetting the text clears consent. While My Profile is enabled, the send-time guard refuses recognizable historical custom instructions whose consent was revoked or whose text differs from the current approved text. Stored history, derived outputs, transformed or compacted text and prior provider copies can persist. Removing consent or disabling the plugin leaves those copies in place. No additional model tool, skill invocation, approval request or network path is registered. In the simplified candidate, saved checked nonempty fields are included in supported native requests to the selected provider, including cloud providers. Unchecked fields are not freshly injected. The Host refuses requests with a recognizable Profile information section no longer authorized while the component is enabled. Previously sent details and derived content can remain in provider systems and conversation history. Legacy record versions never activate old field choices; changed restored values start Private unless the user explicitly acknowledges the imported choices and Saves. Backups are plain JSON and contain personal data. Review & Merge preserves omitted settings. Replace All requires its own confirmation and policy import is separately reviewed. Restore changes the draft until a separate revision-checked Save and clears custom-text sending consent. Downloads use the browser's native Blob download and the Clipboard API; the plugin has no filesystem service. Settings saved by 0.7.1 are migrated only after review and explicit confirmation; per-Workspace permissions are never promoted to profile-wide permissions.

The suite automatically checks the public **latest stable GitHub Release** when its browser module starts and every 24 hours while active; the user may also click **Check again**. These read-only requests omit credentials and referrers and send zero conversation or profile data. No automatic install, shell execution, Host activation, or update attempt occurs during checks.

For **Update now**, the user must explicitly confirm. The browser verifies the release tag's commit SHA and package identity/version, then delegates installation to DSH's native Host updater, which requires an existing Git dependency pinned to a 40-character SHA. Host dependency resolution, compatibility, rollback attempts and restart reporting apply. A failed update may require manual recovery; the suite never claims guaranteed rollback. Unpinned Git installations are not silently migrated.

## Direct Chat and My Profile on develop

The hardening on `develop` strengthens Direct Chat's tool-denial predicate for filesystem symlinks, Windows junctions and not-yet-created child paths under the protected Workspace. It also restricts newly created POSIX Direct Chat directories to owner-only permissions, suppresses sensitive filesystem paths from error logs and marks prepare responses `no-store`. My Profile detects recognized stale disclosure blocks with CRLF, CR and Unicode line separators, and removes additional invisible formatting controls from injected field values. [Reproduction and scope](docs/research/SECURITY_CODE_AUDIT_2026_11_22.md).

Direct Chat prepare and catalog use the same canonical directory checks. DSH's exact Fetch-route dispatcher restricts both routes to owner Peers in the pinned offline Host tests. Prepare can return the Profile-local path to the authorized owner. Catalog discovery returns only the registered Workspace ID and bounded creation metadata, with no message bodies or directory creation. Installed Desktop and remote connection authorization still require testing.

The changes are pending a separate release. Direct Chat shares one Workspace filesystem directory. Path checks and tool-denial hooks are policy controls, with outstanding Desktop validation for alternate tool routes, Windows ACLs and junctions, and time-of-check/time-of-use behavior. My Profile provider tracing and replay checks remain pending. The suite has no filesystem or process sandbox.

This policy describes the current implementation. DSH, the configured model provider and other plugins have their own data handling.
