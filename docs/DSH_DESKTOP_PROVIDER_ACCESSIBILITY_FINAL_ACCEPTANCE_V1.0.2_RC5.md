## D. Provider integration and privacy

The suite consumes the Host's model directory and permission-checked routes. The installed DeepSeek Messages adapter exposed `DeepSeek-V4.1-Flash` and `DeepSeek-V4-Pro`. Native Flash → Pro selection retained the existing conversation. A fresh Pro request serialized on `deepseek-v4-pro`, and a Flash request after restart serialized on `deepseek-flash`. The recorder saw authenticated HTTP requests on the authorized localhost endpoint. Auxiliary title-generation calls were identified separately from primary conversation turns. The retry harness initially matched an earlier marker in a coalesced failed turn. This limits duplicate/retry conclusions and is reported independently of the successful model checks.

Fresh Private and allowed-field controls verified omission and inclusion at the real adapter. A selected fictional field was sent only after explicit Save. A second private field and unrelated Session marker were absent. The previously authorized Session was refused after committed revocation before adapter serialization. A fresh request after revocation omitted the prior field, custom text and earlier Session marker. The final restart confirmed both consents stayed off. A consented custom-text request and an independent fresh omission control passed. Previously sent custom instructions may still be in history. The strict historical field criterion and a repeat of the revoked historical turn after cold restart remain unverified. Keep the existing guard and seek separate approval if the owner wants to accept refusal plus fresh omission as the product contract.

The installed Host's **Models → Add model provider → Custom model API** offered OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and Gemini API. A disposable custom OpenAI Chat Completions route discovered a synthetic model from authenticated localhost. Its primary request had no reasoning-effort field and the renderer displayed the fixture reply. The same conversation then selected DeepSeek Messages and completed an authenticated Flash request. OpenAI Responses, Anthropic Messages, Gemini API and genuine external services remained outside wire coverage. Live external service verification requires an authorized test account.

The installed UI offered Flash levels Off, Low, High and Max, and accepted explicit Off. The suite scopes saved preferences to provider/model, applies an advertised effort only on explicit request, and drops acknowledgements after route or connection changes. Fixture tests cover unavailable/unsupported routes, revisions and deterministic recommendations in English, Arabic and mixed input. The classifier does not persist samples. Native statistics displayed saved usage and unavailable reasoning-token totals. Source and pinned tests handle failure/cancellation accounting, bounded counters, reconstruction, failed reset and explicit retry. No request-local or subagent policy is supported by the effective Host contract.

On the sampled missing rows, `SessionSummary.title` and both authorized title projections were absent. The follow-up distinguished authentic saved native controls from synthetic seeding and reproduced a high-concurrency checkpoint read limit. The installed Windows per-record JSON checkpoint reader requires bounded concurrency or another supported complete projection. Current suite code uses only admitted metadata, prefers the supplied title and warns when the list is incomplete. Use the exact Session ID if known. [H04 follow-up](DSH_DESKTOP_DIRECT_CHAT_H04_FOLLOWUP_V1.0.2_RC3.md)
- **MP02, Blocked.** The product refused the previously authorized Session before any serialized request. This is a verified safety behavior with a remaining historical-wire acceptance gap. Revocation prevents fresh contribution and can refuse recognized replay. It cannot recall already disclosed data or guarantee recognition of paraphrased or compacted content. [rc.2 security acceptance](DSH_DESKTOP_SECURITY_ACCEPTANCE_V1.0.2_RC2.md)
- **Upstream/native gates.** A configured LiveShare relay, authorized viewer and separate Windows principal are needed for live authorization and ACL tests. A usable partial catalog, supported fault timing and a safe installed warning trace are still needed. The pinned Host fixtures do not substitute for those prerequisites.
- **Provider and accessibility limits.** Live external model credentials, real inference quality, full installed cross-provider fault testing and assistive speech output remain outside verified scope. Numeric provider usage is displayed when reported. OS-level scaling and contrast need a native run with a suitable environment.

## J. Security, privacy, upgrade and recovery

My Profile relies on Host settings and OS access controls. Values and backups are plaintext. Only committed allowed nonempty values are freshly injected on supported top-level steps. The existing guard protects recognized old field-disclosure blocks while enabled. Prior transmissions, derived replies and stored history can persist. No settings namespace, guard, provider backend or deletion capability changed in rc.5.

Direct Chat uses one dedicated Workspace for separate native Sessions. Both policy hooks apply through the DSH tool pipeline. An authenticated local owner was the only native identity exercised. The suite offers no OS process or filesystem sandbox. Chat Control remains preview-only. No delete, cleanup job or fictional Session removal was exercised. Neutral route bodies and deliberate source-level redaction were verified independently of the missing native warning case.

The installed Host exposes a separate session-log upload setting for the official model API. It was initially enabled in the disposable Profiles and was explicitly turned off in both. The launcher also set its telemetry-disabled environment flag. The request recorder proves the model adapter's localhost destination and inspected body fields. It did not monitor process-wide egress during the earlier synthetic runs. No real Profile or personal information was used. The later cross-adapter trial ran with the Host setting off.

The controlled upgrade used the immutable published v1.0.0 Git package and a local candidate tarball in the same disposable Profile. The saved fictional turn and Profile values survived, existing field consent stayed Private, and a later cold restart retained committed revocations. Native Plugin Manager reported the installed and browser versions and v1.0.0 as latest stable. The pinned Git update command path and failed-update rollback were outside the completed native scope. The local tarball installation is a supported native CLI upgrade; the automatic or guaranteed reversal of a failed update remains unverified.
