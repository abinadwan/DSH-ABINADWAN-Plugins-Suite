# Chat Control native archive API research

Checked the published DSH `0.2.2-rc.3` client packages used by the suite and upstream source at [`2e39e704`](https://github.com/deepseek-ai/deepseek-harness/tree/2e39e704). The installed Windows Desktop identifies its runtime as `0.2.2-rc.5`. Package declarations and source establish the interfaces below. Runtime acceptance is tracked separately.

| Area | Verified contract | Chat Control integration or fallback |
|---|---|---|
| Cordis and the client plugin | The documented lazy client module loader and scoped Cordis effects own slot registration and disposal. [`Slot API`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/docs/subsystems/slots.md) | Reuse the active Chat Control `settings.section` and its localized native dialog. Disabling the Host component removes the section and its UI. |
| Sidebar view options | The native Workspace browser offers **Hide archived**, **All conversations (show archived)** and **Archived only**. The filter actions belong to the native browser's view store. The public `UiWorkspace` declaration publishes navigation and archive commands and has no setter for the view filter. [`WorkspaceBrowser.tsx`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/client/ui-workspace/src/client/rows/WorkspaceBrowser.tsx), [`navigation.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/client/ui-workspace/src/client/navigation.ts) | Scope the setting to Chat Control. For the native sidebar, direct users to **View options → Hide archived** or the other two native choices. |
| Catalog, metadata and updates | The observable Client lists can temporarily retain values on reconnect. `ctx.remote.workspace.follow(signal)` starts with a complete authorized Workspace baseline. `ctx.remote.session.list({}, signal)` returns authorized Session summaries and projection hints. Neither catalog gives a Session creation or archive date. [`Workspace controller`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/api/workspace-controller/README.md), [`Session controller`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/api/session-controller/README.md), [`Workspace storage`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/workspace/workspace/README.md) | Use the observable lists to refresh the view. Require fresh native metadata and unique Workspace membership. Bind responses to the connection generation and cancel reads when it changes. |
| Search and filtering | The sidebar owns its archive-aware title search. The public Session search also supports content search. [`Web Client`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/docs/subsystems/web-client.md), [`Session controller`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/api/session-controller/README.md) | Filter the authorized snapshot locally by Session title, Workspace title, protection, pin and last-update date. Never request content or read storage. |
| Opening and restoring | Native UI requires unarchive before opening an archived row. `ctx.workspaces.unarchiveSession(sessionId)` calls `workspace/unarchiveSession` and installs the confirmed archive set. The Host treats repeat unarchive as a no-op. The endpoint accepts only Session ID. It cannot atomically check Chat Control protection, Workspace membership or an expected revision. Archiving clears native pin and restoring does not re-pin. [`Workspace controller`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/api/workspace-controller/README.md), [`Web Client`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/docs/subsystems/web-client.md) | Confirm manually, then fetch fresh catalogs and `settings.describe`. Check the confirmed Settings revision, protection, pin, connection and access before the native command. Browsing is read-only. |
| Authorization and profile | Gateway authorizes each remote call and filters catalog records. `ctx.uiSession.whenAccess` supplies live Session-scoped eligibility, and the native Client Connection exposes its active generation. Settings belong to the active Host profile. The native liveshare policy classifies Settings description and replacement as owner-only. [`Remote access`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/api/remote-access/README.md), [`Profiles`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/docs/architecture.md), [`Liveshare policy`](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e704/packages/experimental/liveshare/src/endpoint-classification.ts) | Require authorized Chat Control settings before listing. Restore additionally requires live `workspace/unarchiveSession` access on the target Session. Persist the display preference in the existing Host Settings record. Discard in-flight UI state across connection generations. |

The implementation reuses `client.js`'s scoped Settings surface and metadata join. The native modal owns its dialog and keyboard behavior. The Host schema adds a backward-compatible display preference, and the archive view consumes the native live catalog and unarchive command. Existing retention previews and direct-chat separation continue to use their established scopes.
