## Safe deletion feasibility

The five reviewed competing plugins demonstrate variations of physical removal, registry cleanup, private retirement, polling, activity checks and recycle/trash. Their concrete approaches and failure modes are recorded in the [Phase A comparison](NEW_PLUGINS_PHASE_A.md#conversation-lifecycle). The present investigation used native package contracts directly and independently implemented only synthetic probes.

| Candidate | Findings and decision |
|---|---|
| **Native archive then purge** | `WorkspaceRegistry.archiveSession` queries `workspace/session-activity` before a durable archive flag and may optionally stop work. The reviewed archive guard is `agent/pre-step`, after an Agent may already be resolved and own persistence. Cold reads remain valid. Archive keeps history and membership. Even with stop disabled it supplies neither an activation lease nor a deletion transaction. |
| **Native writer lease plus independent removal** | Two independent native persistence instances on one synthetic root confirmed that `open(id, 'write')` rejects while a writer holds ownership. A new reader opened successfully during that lease. After closure a new writer acquired immediately. On Windows the semaphore excludes competing writers but does not fence directory access. Obtaining a write handle can also publish a new format generation for a historical session. A writer probe cannot guarantee absent activity, reader closure, immutable artifact inventory or retirement. |
| **Context-owned teardown plus lock** | A plugin can dispose native Agents it owns and let normal close drain their writers. Ordinary Workspace Agents belong to other Host services. `whenIdle()` is a point-in-time wait and the public close path releases its ownership. There is no supported cross-owner reservation that prevents new prompt, resume, queue, job, descendant, retained view and read admission while an independent component commits. |
| **Fully quiesced maintenance with restart reconciliation** | After disposing every Host in the fixture, a test removed one canonical synthetic log inside its verified scratch root. On restart native `stat()` lost only that session and SQLite search reconciled. The archive ID remained durable, and the independent log and fictional project-file bytes were unchanged. This proves that omission from search and storage does not establish complete native cleanup. The test is limited to one current generation and one synthetic Host composition. |
| **Independent maintenance across native services** | Native detach and unarchive handle their own metadata. FTS converges on the next stable search. Projection checkpoints and archive/pin data have separate ownership. `stat().location` names the selected generation and is not a complete artifact set. The installed contracts provide no public atomic retirement plan spanning durable logs, their previous generations, relationship metadata and projection checkpoints. Win32 real-path validation was investigated, but the reparse-point fixture could not run in this sandbox. |

The missing contract is a Host-owned per-session retirement reservation honored by every source of activation, reading and activity, plus authoritative generation enumeration and a restart-safe native cleanup commit or equivalent verified recovery protocol for all affected metadata and indexes. A restricted cold-maintenance operation would also need an authoritative way to enforce quiescence across processes and windows before it can be offered. Workspace ownership must be positive and authoritative. Harness documents only one Workspace membership per session, so inconsistent duplicates should be treated as ambiguous. Direct Chat preset and ledger mismatches remain excluded. Storage containment must reject drift and reparse redirects under an authenticated storage root. An unresolved check cannot grant deletion.

Production filesystem deletion or private workarounds would need separate approval after these guarantees are established. Automatic policies default to Keep forever. Informed consent covers each enabled or changed policy revision after a preview. Once a safe engine is available and the exact policy is activated, its scheduled executions may proceed with eligibility rechecks and report outcomes without daily confirmation. Manual deletion still needs explicit confirmation.

## Reproduce the isolated checks

From the assigned worktree, give the extractor the installed Desktop archive path. It reads packaged dependencies into an ignored `node_modules/.new-plugins-qa/<build>/` folder within the worktree. No active Desktop profile is loaded. The fixture uses fresh synthetic scratch directories under `node_modules` and removes only those directories on teardown.

```powershell
node qa/extract-new-plugins-runtime.mjs 'C:\Users\Admin\AppData\Local\Programs\DeepSeek Harness\resources\app.asar'
$env:ABINADWAN_TEST_RUNTIME = (Resolve-Path 'node_modules/.new-plugins-qa/6b729fedde0c8fd03af7afdf5a711aa64fe87c3b').Path
node --test qa/new-plugins-host-check.mjs
node scripts/render-plugin-icons.mjs $env:ABINADWAN_TEST_RUNTIME --check
```

Omit `--check` to regenerate the artwork. The renderer is a development tool and does not add a suite runtime dependency. The Host fixture records elapsed time for two single-request smoke cases against an offline adapter. Cold/warm order and local fixture overhead affect those timings. They support no provider latency, cost or performance claim.

The Windows junction case reports a skip when Windows or its sandbox denies creation. The full existing suite needs the exact npm lockfile dependencies. This environment returned `ENOTCACHED` in offline mode and `ENOTFOUND registry.npmjs.org` in network mode. The attempted existing suite failed at imports for missing dependencies such as `@deepseek-ai/schemastery`; the isolated fixture ran using the bundled packages. Existing artwork, shared production files, Personal Profile implementation and Phase 7D files remain unchanged.
