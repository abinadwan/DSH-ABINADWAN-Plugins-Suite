## Direct Chat ownership admission

The exact-build fixture attaches an inherited tool mask and a monotonic dispatch guard during the awaited `agent/created` event. It identifies candidate sessions from their original native preset marker or a durable ownership record. Its pre-step listener requires the original marker and a matching ready record. Pending, missing and conflicting records produce zero adapter requests. The first ready message reaches the adapter with an empty tool list, and a subsequent model change reaches the newly selected model with the same restriction. An ordinary Workspace control keeps its fictional terminal. [Native fixture](../../qa/new-plugins-host-check.mjs)

The native preset service still accepts a change on a blank session and records the selected preset separately from the original header. The Agent-scoped mask and guard survive that change. Inherited masks leave Agent-local registrations visible, but the active guard still denies dispatch of the synthetic local registration. The stock lock after the first turn applies to all sessions. It provides no ownership-specific authorization. [Preset service](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/preset/agent-preset-registry/README.md#L54-L60) · [Tool scope and guards](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/core/tools/README.md#L86-L94)

A native restart with the test policy loaded reapplies the restrictions to the newly created Agent. A second restart without the policy still resumes the session, reads its retained header and ledger, and sends the inherited fictional terminal schema to the offline adapter. Stock API resume composes the projected current preset. The documented plugin listener is optional and the guard is scoped to native tool dispatch. Native file actions are served by the session controller through their own authorization, so this fixture cannot prove denial at every command, terminal or filesystem entry point. The product gate requires Host-owned authorization on create or reuse, preset changes, resume and first-message admission, and equivalent checks on native actions. It must fail closed when the ownership policy is unavailable. Native Direct Chat text and image rendering are deferred until that gate is met. Upload-only generic files and custom transcript storage are independent requirements. [Agent creation contract](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/core/agent-loop/README.md#L109-L118) · [API Agent activation](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/api/session-controller/src/agent.ts) · [Session file actions](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/packages/api/session-controller/src/index.ts#L328-L391)

## Offline deletion feasibility

| Guarantee | Evidence and conclusion |
|---|---|
| Authoritative shutdown and restart exclusion | The packaged Desktop acquires Electron's `requestSingleInstanceLock` for Desktop, with its own shutdown handlers. The independent Host and CLI persistence service uses a per-session writer lease. No public maintenance admission was found that every Desktop, CLI and standalone Host startup must honor. After orderly disposal of the isolated native Host, a test wrote a synthetic pending maintenance journal and started a second Host. It acquired the same session writer successfully. The journal is advisory without a startup consumer. |
| Enforceable reader/writer exclusion | The Win32 backend uses a session-named semaphore. The native fixture admits a reader during the lease and admits another writer after closure. Desktop's own app instance lock does not establish exclusion across CLI or other Hosts using the same persistence root. Process enumeration, waiting for exit, and holding an application-specific lock would leave the restart race open. |
| Exact artifact and metadata coverage | `stat().location` names one selected generation. The native provider may keep earlier generations and publish a successor when opening a historical log for write. The installed APIs do not provide an authoritative retirement manifest across generations, related sessions or projection checkpoints. Native unarchive and unpin are individual operations, review of positive Workspace ownership must precede removal, and FTS reconciles independently. The isolated removal probe leaves the native archive ID after restart despite search reconciliation. |
| Windows containment and Workspace preservation | The actual synthetic junction passed lexical containment while resolving outside the synthetic transcript root. The removal fixture checks a strict canonical descendant and explicitly rejects the sibling path shape. The unrelated transcript and fictional project file retained byte identity. Production containment would also need reparse-aware handle-based traversal, stable identities and verified containment at every destructive step. |
| Journal and idempotent recovery | A durable journal would need phases for exact admitted identities and revisions, verified removal, separate metadata convergence, and final released state. The restart probe shows there is no native actor that prevents a new Host from accessing a half-finished operation. Recovery cannot be made authoritative by having the same maintenance tool read its own journal. |
| Exclude Direct Chat | Positive Workspace membership and durable Direct ownership are both needed. The native preset-switch test shows the current preset may differ from the creation preset, so a current preset projection cannot replace the ownership ledger and immutable origin check. Unknown, pending and conflicting records cannot be admitted for deletion. |

Stop the independent offline deletion path at this build. The earliest missing prerequisite is an enforceable maintenance lease honored by all process entry points through restart. It would still require authoritative artifact enumeration and restart-safe completion across native metadata owners. No production deletion engine, recovery journal, staging area, backup, recycle bin or encryption was added.
