# Phase 7B candidate — response preferences runtime integration

Status: implementation candidate, not a release. Base 0.7.2; research PR #19. Host pin 38a6a5c965aa99ab525161efb7cc5cf1fe62fced.

- Native optional systemPrompt.section registration on the Personal Profile fiber; no Workspace dependency or slash command. Stable name, order 50, literal interpolation disabled. Reads volatile record.get() at assembly; supported top-level native scoped steps with non-aborted signal and provider/model selection; excludes marked delegated children and diagnostic assemblies. Complete prompts may override the section. Auxiliary scopes and actual Desktop behavior still require verification.
- Style/language/traits/presets are preferences, subordinate to host and current user task. Neutral preferences contribute nothing. Free-form text is local until explicit send consent is saved. Consent includes cloud models and history retention; edits, migration, restore and reset clear consent. Historic prompts, derived messages and provider copies cannot be erased or recalled by this plugin.
- Optional v2 preferences.sendCustom boolean: missing means off; no version change. Old backups remain readable. Export includes true when set; restore intentionally clears it regardless of structured permission restore. No new dependency, storage engine, RPC, filesystem service or network client. Downgrading an exported record with this new key may require removing the key for the old strict decoder.
- Structured information, access and cloud switches remain inactive; no field is rendered, regardless of policy. Phase 7C is blocked as explained in Phase 7A. Custom text can contain sensitive values manually typed by user; consent is not a classifier.
- Browser has a lazy CJS module contract, so candidate mirrors the catalog and renderer into an ESM helper and verifies exact parity in tests rather than introducing an unverified browser module loader mechanism. 
- Tests: pure renderer/consent/field exclusion, scope checks, real Cordis lifecycle with registry double, UI consent checks. Full pinned SystemPrompt + Agent Loop/fake adapter integration and Windows tests are still required before release. Existing no-network/browser/permission assertions retained; previous no-agent Host test intentionally replaced with independent service attachment check.
- No version bump, no merge, no release. Before acceptance, test real committed Save on next step, unsaved draft ignored, disable/re-enable, resumed and concurrent sessions, complete prompts, history/retry semantics, both restore modes, custom opt-in, no structured PII, Humanizer and Environment & Context.
